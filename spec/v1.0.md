# Zest Specification v1.0

Formal specification for the Zest LTI content platform. This document covers the `zest.json` manifest format, the Bridge API, content file conventions, assessment configuration, and server API endpoints.

**Audience:** Content developers building Zestables (interactive content packages for the Zest platform).

**Spec Version:** 1.0
**Bridge API Version:** 3.0.0

## 1. zest.json Manifest

Every Zest content package should include a `zest.json` manifest file at the same directory level as `index.html`. This file declares metadata, grading behavior, parameters, sandbox permissions, and references to supplementary files.

### Full Schema

```json
{
  "zestSpec": "1.0",
  "name": "Forces and Motion: Basics",
  "version": "3.0.0",
  "description": "Explore forces and motion with PhET.",
  "grading": "auto",
  "editorFile": "editor.html",
  "assessmentFile": "assessment.json",
  "reviewFile": "review.html",
  "answerKey": "answer-key.json",
  "parameters": [
    {
      "key": "defaultScreen",
      "type": "select",
      "default": "",
      "options": ["", "net-force", "motion", "friction"],
      "label": "Starting Screen"
    }
  ],
  "sandbox": {
    "allowScripts": true,
    "allowSameOrigin": true,
    "allowPopups": false,
    "allowForms": false
  },
  "tags": ["physics", "forces", "phet"],
  "allowedDomains": ["cdn.jsdelivr.net"],
  "width": 900,
  "height": 700,
  "attribution": {
    "source": "PhET Interactive Simulations",
    "license": "CC BY 4.0",
    "url": "https://phet.colorado.edu"
  }
}
```

### Field Reference

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `zestSpec` | `string` | No | `"1.0"` | Spec version. Currently always `"1.0"`. |
| `name` | `string` | No | `"Untitled Content"` | Display name for the content. Used as the title if no title is provided during upload. |
| `version` | `string` | No | `null` | Content version (semver recommended). Informational only. |
| `description` | `string` | No | `null` | Brief description of the content. |
| `grading` | `"none"\|"auto"\|"teacher"` | No | `"none"` | Grading mode. `"none"` = no grades. `"auto"` = content submits scores via Bridge API. `"teacher"` = work submitted for manual grading in SpeedGrader. When set to `"auto"` or `"teacher"`, the content is automatically treated as interactive (ltiResourceLink). |
| `editorFile` | `string\|null` | No | `null` | Path to `editor.html` for teacher config editing. Relative to the manifest directory. Added in Sprint 9.5. |
| `assessmentFile` | `string\|null` | No | `null` | Path to `assessment.json` default assessment configuration. Relative to the manifest directory. Added in Sprint 9.5. |
| `reviewFile` | `string\|null` | No | `null` | Path to `review.html` for SpeedGrader review view. Relative to the manifest directory. |
| `answerKey` | `string\|null` | No | `null` | Path to an answer key JSON file. On upload, this file is moved to the `.secure/` directory (never served to students). Available to instructors in review mode. |
| `parameters` | `array` | No | `[]` | Per-placement parameters configurable via LTI custom variables. See [Parameters](#parameters) below. |
| `sandbox` | `object` | No | See below | Iframe sandbox token configuration. See [Sandbox](#sandbox) below. |
| `tags` | `string[]` | No | `[]` | Tags for categorization and filtering. Merged with auto-generated tags (year, source type, course title) on upload. Normalized to lowercase, trimmed, deduplicated. |
| `allowedDomains` | `string[]` | No | `[]` | External domains allowed in Content Security Policy. Merged with server-level `ZEST_ALLOWED_DOMAINS`. Opt-in: if neither is set, only `frame-ancestors` CSP applies. |
| `width` | `number` | No | `800` | Default iframe width in pixels (200--2000). |
| `height` | `number` | No | `600` | Default iframe height in pixels (100--2000). |
| `attribution` | `object` | No | `null` | Source attribution. Fields: `source` (string), `license` (string), `url` (string). |

### Parameters

The `parameters` array defines configurable values that teachers can set per-placement via the picker UI. Students receive resolved values through the Bridge API.

Each parameter object:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `key` | `string` | Yes | Unique identifier. Passed to content as `zest_param_<key>` LTI custom variable. |
| `type` | `"text"\|"select"\|"number"\|"boolean"` | Yes | Input type for the picker UI. |
| `default` | `any` | No | Default value when no teacher override is set. |
| `options` | `string[]` | Conditional | Required when `type` is `"select"`. Array of allowed values. |
| `label` | `string` | No | Human-readable label shown in the picker UI. |

### Sandbox

The `sandbox` object controls which iframe sandbox tokens are applied. All boolean fields default to `false` unless specified.

| Field | Type | Default | Sandbox Token |
|-------|------|---------|---------------|
| `allowScripts` | `boolean` | `false` | `allow-scripts` |
| `allowSameOrigin` | `boolean` | `false` | `allow-same-origin` |
| `allowPopups` | `boolean` | `false` | `allow-popups` |
| `allowForms` | `boolean` | `false` | `allow-forms` |

If no `sandbox` object is provided, the server applies the default sandbox: `allow-scripts allow-same-origin`.

## 2. Bridge API Reference

The Bridge API is a client-side JavaScript library that content includes to communicate with the Zest platform. It handles user context, grading, state persistence, and assessment configuration.

### Including the Bridge

```html
<script src="https://YOUR_ZEST_SERVER/public/zest-bridge.js"></script>
```

All methods are available on the global `window.Zest` object after the script loads.

### Core

| Method / Property | Returns | Description |
|-------------------|---------|-------------|
| `Zest.version` | `string` | Bridge API version string. Currently `"3.0.0"`. |
| `Zest.onReady(callback)` | `void` | Register a callback that fires when LTI user context is received. The callback receives the full context object. If the bridge is already ready, fires immediately. |
| `Zest.getContext()` | `object\|null` | Returns the full context object, or `null` if not yet received. |
| `Zest.getUser()` | `object\|null` | Returns `{ id, name, email, roles, courseId, courseTitle }` extracted from the context, or `null`. |
| `Zest.isStudent()` | `boolean` | `true` if the current user has the `Learner` role. |
| `Zest.isTeacher()` | `boolean` | `true` if the current user has the `Instructor` role. |
| `Zest.setHeight(px)` | `void` | Request the wrapper to resize the content iframe to the given height in pixels. No-op in external tab mode. Note: Canvas CSS prevents resize on assignment external tools; works on page embeds. |
| `Zest.isReady()` | `boolean` | `true` if the context has been received. |
| `Zest.isExternalTab()` | `boolean` | `true` if the content is running in a standalone browser tab (not nested in an LTI iframe). In this mode, the bridge makes direct fetch calls instead of postMessage relay. |
| `Zest.isReviewMode()` | `boolean` | `true` if the content is loaded in SpeedGrader review mode. |

### Grading

| Method | Returns | Description |
|--------|---------|-------------|
| `Zest.submitScore(score, options?)` | `Promise<{success, error?}>` | Submit an auto-graded score. `score` is a number from 0 to `maxScore`. Options: `{ maxScore: number (default 100), artifacts: object, comment: string }`. Posts to Canvas AGS with `gradingProgress: 'FullyGraded'` -- score appears in the gradebook immediately. |
| `Zest.submitWork(options?)` | `Promise<{success, error?}>` | Submit student work for teacher grading (no score). Options: `{ artifacts: object, comment: string }`. Posts to Canvas AGS with `gradingProgress: 'PendingManual'` -- gradebook shows "Submitted" and the teacher grades in SpeedGrader. |
| `Zest.getSubmission()` | `object\|null` | Returns submission data when in review mode. Contains the student's submitted artifacts, score, comment, and timestamp. |
| `Zest.getAnswerKey()` | `object\|null` | Returns answer key data in review mode (instructor only). Loaded from the `.secure/` directory. |

### State Persistence

State uses a three-tier storage model: in-memory (undo/redo) -> localStorage (immediate) -> server (periodic sync every 60 seconds). State is keyed by `contentId + assignmentId + userId`.

| Method | Returns | Description |
|--------|---------|-------------|
| `Zest.saveState(data)` | `void` | Save any JSON-serializable data. Writes to localStorage immediately and marks the state as dirty for server sync. Pushes the previous state onto the undo stack (max 50 entries). |
| `Zest.loadState()` | `Promise<data\|null>` | Load saved state. On the first call, compares localStorage and server timestamps and returns the newer one. Subsequent calls return from localStorage (fast). Returns `null` if no state exists. |
| `Zest.undo()` | `data\|null` | Pop the previous state from the in-memory undo stack. Returns `null` if nothing to undo. Per-session only (undo history is not persisted). |
| `Zest.redo()` | `data\|null` | Pop the next state from the in-memory redo stack. Returns `null` if nothing to redo. |
| `Zest.hasUnsyncedChanges()` | `boolean` | `true` if localStorage state differs from the last server-synced state (hash comparison). |
| `Zest.onSyncStatus(callback)` | `void` | Register a callback for sync status changes. Fires immediately with the current status, then on each change. Status values: `'syncing'`, `'synced'`, `'dirty'`, `'error'`. |
| `Zest.clearState()` | `Promise<{success, error?}>` | Clear all saved state: localStorage, undo/redo stacks, and server record. Use to reset a student's progress. |
| `Zest.syncNow()` | `Promise<{success, status?, error?}>` | Force an immediate sync to the server. Returns `{ status: 'already_synced' }` if no changes, or `{ status: 'nothing_to_sync' }` if no state exists. |

### Content Config (Sprint 9.5)

These methods support the assessment configuration system, allowing content to load teacher-customized configs and editors to save them.

| Method | Returns | Description |
|--------|---------|-------------|
| `Zest.getAssessmentConfig()` | `object\|null` | Synchronous. Returns the assessment config that was provided at launch time via the `zest-context` message. This is the resolved config after the cascade lookup (see [Config Cascade](#5-config-cascade)). Returns `null` if no config is available. |
| `Zest.getConfig(assignmentId?)` | `Promise<{success, config?, source?, error?}>` | Load config from the server. The `source` field indicates where the config was found: `'override'`, `'content-default'`, `'default'` (from zip), or `'none'`. If `assignmentId` is omitted, defaults to the current context's assignment ID. |
| `Zest.saveConfig(data, assignmentId?)` | `Promise<{success, error?}>` | Save config to the server. Instructor-only. Creates or updates a config record in the `zest_content_config` table. |
| `Zest.deleteConfig(assignmentId?)` | `Promise<{success, error?}>` | Delete a config override from the server. Instructor-only. After deletion, the cascade falls back to the next level. |

### Parameters

| Method | Returns | Description |
|--------|---------|-------------|
| `Zest.getParameters()` | `object\|null` | Returns all per-placement parameters as a key-value object, or `null` if none are set. Parameters are injected by the LTI launch as custom variables prefixed with `zest_param_`. |
| `Zest.getParameter(key, default?)` | `any` | Returns a single parameter value. Falls back to `default` if the parameter is not set (or `null` if no default is provided). |

### Server Info

| Method | Returns | Description |
|--------|---------|-------------|
| `Zest.getServerInfo()` | `Promise<{specVersion, bridgeVersion, serverVersion, capabilities[]}>` | Fetch server capabilities and version info. Results are cached after the first call. Calls `GET /api/info` on the server. |
| `Zest.supportsCapability(name)` | `boolean` | Check if the server supports a named capability. Requires `getServerInfo()` to have been called first. |

**Known capabilities:**

| Capability | Description |
|------------|-------------|
| `grading.auto` | Auto-graded submissions via `submitScore()` |
| `grading.teacher` | Teacher-graded submissions via `submitWork()` |
| `state.persistence` | Student state save/load |
| `state.sync` | Periodic server sync of state |
| `review.speedgrader` | SpeedGrader review integration |
| `review.answerkey` | Answer key support in review mode |
| `parameters` | Per-placement parameters |
| `sandbox.configurable` | Content-declared sandbox overrides |
| `domains.allowlist` | CSP domain allowlisting |
| `fullscreen` | Fullscreen button support |
| `external.tab` | External tab mode |
| `assessment.config` | Assessment config CRUD API |

## 3. Content File Conventions

A Zest content package is a zip file (or `.zest` file) containing web assets. The following file conventions are recognized by the platform.

| File | Required | Description |
|------|----------|-------------|
| `index.html` | **Yes** | Main content entry point. The platform locates this file automatically (at the root, inside a single wrapper folder, or up to 3 levels deep). |
| `zest.json` | **Yes** (recommended) | Content manifest. Must be at the same directory level as `index.html`. Declares metadata, grading mode, parameters, sandbox config, and file references. |
| `bridge.js` | No | Content-specific bridge logic. Typically imports and initializes the Zest Bridge for the content's needs. |
| `assessment-panel.js` | No | Collapsible assessment panel script. Used by content that integrates with the assessment config system to display explore/quiz UI. |
| `assessment.json` | No | Default assessment configuration file. Declared in `zest.json` as `assessmentFile`. Provides the baseline config before any teacher overrides. See [Assessment Config Schema](#4-assessment-config-schema). |
| `editor.html` | No | Teacher config editor page. Declared in `zest.json` as `editorFile`. Served at `/editor/:contentId` in an instructor-only wrapper. Uses the Bridge API to load, modify, and save assessment configs. |
| `review.html` | No | SpeedGrader review view. Declared in `zest.json` as `reviewFile`. Loaded instead of `index.html` when the content is viewed in Canvas SpeedGrader. Receives submission data and answer key via the Bridge API. |
| `.secure/` | No | Secure directory. Files in this directory are never served to students via the `/content/*` route. Used for answer keys and sensitive data. Created automatically when an `answerKey` is declared in `zest.json` -- the answer key file is moved here on upload. |

### Allowed File Types

The following extensions are permitted inside zip uploads:

- **HTML:** `.html`, `.htm`
- **CSS:** `.css`
- **JavaScript:** `.js`, `.mjs`
- **Images:** `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.webp`, `.ico`, `.bmp`, `.avif`
- **Fonts:** `.woff`, `.woff2`, `.ttf`, `.eot`, `.otf`
- **Audio/Video:** `.mp3`, `.wav`, `.ogg`, `.mp4`, `.webm`, `.ogv`
- **Data:** `.json`, `.xml`, `.csv`, `.txt`, `.md`
- **Other:** `.map`, `.wasm`, `.glb`, `.gltf`, `.obj`, `.mtl`, `.pdf`

### Upload Limits

- Maximum zip file size: **100 MB**
- Maximum file count: **500 files**
- Maximum individual file size: **50 MB**
- Maximum compression ratio: **100:1** (zip bomb defense)
- Symlinks are removed after extraction

## 4. Assessment Config Schema

The assessment config defines two modes: **explore** (guided text prompts) and **quiz** (auto-graded questions). A single config file can contain both modes; the active mode is selected by the `mode` field.

### Full Schema

```json
{
  "version": "1.0.0",
  "mode": "explore",
  "explore": {
    "steps": [
      {
        "id": "predict",
        "title": "Predict",
        "prompt": "Before exploring, predict what will happen...",
        "type": "text",
        "required": true,
        "minLength": 20
      },
      {
        "id": "explore",
        "title": "Explore",
        "prompt": "Use the simulation to test your prediction...",
        "type": "text",
        "required": true,
        "minLength": 30
      }
    ]
  },
  "quiz": {
    "questions": [
      {
        "id": "q1",
        "type": "multiple_choice",
        "prompt": "What happens to an object at rest with no net force?",
        "options": [
          "It accelerates",
          "It remains at rest",
          "It moves at constant speed",
          "It decelerates"
        ],
        "correctIndex": 1,
        "points": 20
      },
      {
        "id": "q2",
        "type": "true_false",
        "prompt": "Friction always opposes the direction of motion.",
        "correctAnswer": true,
        "points": 20
      }
    ],
    "maxScore": 100,
    "shuffleQuestions": false,
    "shuffleOptions": true,
    "showFeedback": true
  }
}
```

### Top-Level Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `version` | `string` | Yes | Config schema version. Currently `"1.0.0"`. |
| `mode` | `"explore"\|"quiz"` | Yes | Which assessment mode is active. Both sections can be present in the file; `mode` selects which one the panel displays. |

### Explore Mode

The `explore` object defines a sequence of guided text-response steps. This mode is teacher-graded (submitted via `Zest.submitWork()`).

**`explore.steps[]` fields:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `string` | Yes | Unique step identifier. Used as the key in submitted artifacts. |
| `title` | `string` | Yes | Step title displayed in the panel header. |
| `prompt` | `string` | Yes | Instructions or question shown to the student. |
| `type` | `"text"` | Yes | Input type. Currently only `"text"` is supported. |
| `required` | `boolean` | No | Whether the step must be completed before submission. Default `false`. |
| `minLength` | `number` | No | Minimum character count for the text response. |

### Quiz Mode

The `quiz` object defines auto-graded questions. This mode submits scores via `Zest.submitScore()`.

**`quiz.questions[]` fields:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `string` | Yes | Unique question identifier. |
| `type` | `"multiple_choice"\|"true_false"` | Yes | Question type. |
| `prompt` | `string` | Yes | The question text. |
| `options` | `string[]` | Conditional | Answer choices. Required when `type` is `"multiple_choice"`. |
| `correctIndex` | `number` | Conditional | Zero-based index of the correct answer in `options`. Required when `type` is `"multiple_choice"`. |
| `correctAnswer` | `boolean` | Conditional | The correct answer. Required when `type` is `"true_false"`. |
| `points` | `number` | Yes | Point value for the question. |

**`quiz` top-level settings:**

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `maxScore` | `number` | No | Sum of all `points` | Maximum possible score. |
| `shuffleQuestions` | `boolean` | No | `false` | Randomize question order per student. |
| `shuffleOptions` | `boolean` | No | `false` | Randomize answer option order for multiple-choice questions. |
| `showFeedback` | `boolean` | No | `false` | Show correct/incorrect feedback after submission. |

## 5. Config Cascade

When the server resolves an assessment config for a given content item and assignment, it follows a four-level cascade. The first non-null result is used.

| Priority | Source | Location | Description |
|----------|--------|----------|-------------|
| 1 | Per-placement override | `zest_content_config` table, `contentId` + `assignmentId` | Teacher-customized config for a specific assignment. Created via the editor or `Zest.saveConfig()` with an `assignmentId`. |
| 2 | Content-level default | `zest_content_config` table, `contentId` + `assignmentId=''` | Teacher-customized default for all placements of this content. Created via `Zest.saveConfig()` with an empty `assignmentId`. |
| 3 | Default from zip | `assessment.json` on disk | The `assessmentFile` extracted from the uploaded zip. The original default config that ships with the content. |
| 4 | null | -- | No config available. `Zest.getAssessmentConfig()` returns `null`. |

The `source` field in the `Zest.getConfig()` response indicates which level was matched:

- `"override"` -- priority 1
- `"content-default"` -- priority 2
- `"default"` -- priority 3
- `"none"` -- priority 4

### Config Storage

Configs are stored in the `zest_content_config` PostgreSQL table:

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key. |
| `contentId` | UUID | References the content item. |
| `assignmentId` | STRING(50) | Canvas assignment ID, or empty string for content-level default. |
| `config` | JSONB | The assessment config object. |
| `updatedBy` | STRING(255) | Name of the instructor who last modified the config. |
| `createdAt` | TIMESTAMP | Record creation time. |
| `updatedAt` | TIMESTAMP | Record last modification time. |

A unique index on `(contentId, assignmentId)` ensures one config per content-assignment pair.

## 6. Event Log Schema

Content can store an event log in the student state to track interactions for analytics and review. The log follows a compact format optimized for storage efficiency.

### Structure

```json
{
  "events": [
    { "t": 1708650000, "type": "session_start", "data": {} },
    { "t": 1708650005, "type": "sim_ready", "data": {} },
    { "t": 1708650012, "type": "screen_change", "data": { "screen": "net-force" } },
    { "t": 1708650045, "type": "interaction", "data": { "action": "drag", "target": "figure-blue-1" } },
    { "t": 1708650090, "type": "answer_update", "data": { "questionId": "q1", "selected": 2 } },
    { "t": 1708650120, "type": "submission", "data": { "score": 80, "maxScore": 100 } }
  ]
}
```

### Event Fields

| Field | Type | Description |
|-------|------|-------------|
| `t` | `number` | Unix timestamp in seconds (not milliseconds). |
| `type` | `string` | Event type identifier. |
| `data` | `object` | Event-specific payload. |

### Standard Event Types

| Type | Description | Typical Data |
|------|-------------|--------------|
| `session_start` | Student opened the content. | `{}` |
| `sim_ready` | Simulation finished loading. | `{}` |
| `screen_change` | Student navigated to a different screen/section. | `{ screen: string }` |
| `interaction` | Student interacted with the simulation. | `{ action: string, target: string, ... }` |
| `answer_update` | Student changed an answer in the assessment. | `{ questionId: string, selected: any }` |
| `submission` | Student submitted their work or score. | `{ score: number, maxScore: number }` |

### Limits

- Maximum **500 events** per student (ring buffer -- oldest events are dropped when the limit is reached).
- Events are stored as part of the student state via `Zest.saveState()`, subject to the 10 MB state size limit.

## 7. Server API Endpoints

All authenticated endpoints require an `ltik` query parameter (LTI session token) unless marked as public. Endpoints marked with **(instructor)** require the `Instructor` or `Administrator` LTI role.

### Public Endpoints

These are whitelisted and do not require LTI authentication.

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/info` | Server info and capabilities. Returns `{ specVersion, bridgeVersion, serverVersion, capabilities[] }`. Used by the Bridge for version negotiation. |
| `GET` | `/health` | Health check. Returns `{ status: 'ok', version, uptime }`. |
| `GET` | `/content/:uuid/*` | Static file serving for uploaded content. Includes CSP headers. Files in `.secure/` directories are blocked (403). |
| `GET` | `/public/*` | Public static assets (Bridge JS, picker UI, icons). |

### Upload and Content Management

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `POST` | `/api/upload` | Instructor | Upload a zip/zest file or save a URL. Parses `zest.json`, extracts answer keys, returns a deep linking response. Accepts `multipart/form-data` with a `zipFile` field. |
| `GET` | `/api/content` | Instructor | List content with search, tag filtering, and pagination. Query params: `search`, `tags` (comma-separated), `limit` (default 20, max 100), `offset`. |
| `GET` | `/api/content/tags` | Instructor | List all unique tags with counts. |
| `POST` | `/api/select` | Instructor | Select an existing content item and return a deep linking response. Body: `{ contentId }`. |
| `DELETE` | `/api/content/:contentId` | Instructor (owner or admin) | Delete content. Blocked if submissions exist. |
| `PATCH` | `/api/content/:contentId` | Instructor (owner or admin) | Update content settings. Editable fields: `title`, `width`, `height`, `autoHeight`, `permissions`, `tags`, `sandboxOverride` (admin only). |

### Grading

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `POST` | `/api/grades/:contentId` | LTI session | Submit a grade or work. Body: `{ score, maxScore, artifacts, comment }`. When `score` is `null`, treated as teacher-graded (`PendingManual`). When `score` is a number, treated as auto-graded (`FullyGraded`). Creates a Submission record and posts to Canvas AGS if a lineitem is available. |

### Student State

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/state/:contentId` | LTI session | Load student state. Query: `?assignmentId=<string>`. Returns `{ success, state, hash, updatedAt }`. |
| `PUT` | `/api/state/:contentId` | LTI session | Save student state. Body: `{ state, hash, assignmentId }`. Hash must be a 32-character MD5 hex string. Hash-based dedup: if the hash matches the stored value, no write occurs (returns `status: 'unchanged'`). |
| `POST` | `/api/state/:contentId` | LTI session | Same as PUT. Accepts `text/plain` content type for `navigator.sendBeacon` on page unload. |
| `DELETE` | `/api/state/:contentId` | LTI session | Clear student state. Query: `?assignmentId=<string>`. |

State size limit: **10 MB** per student per content per assignment.

### Assessment Config (Sprint 9.5)

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/config/:contentId` | LTI session | Load assessment config with cascading lookup. Query: `?assignmentId=<string>`. Returns `{ success, config, source }` where `source` is `'override'`, `'content-default'`, `'default'`, or `'none'`. |
| `PUT` | `/api/config/:contentId` | Instructor | Create or update assessment config. Body: `{ config: {...}, assignmentId?: string }`. Upserts the record. |
| `DELETE` | `/api/config/:contentId` | Instructor | Delete assessment config. Query: `?assignmentId=<string>`. After deletion, the cascade falls through to the next level. |

### Wrapper Routes

These routes serve HTML wrapper pages that iframe content with appropriate context injection.

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/embed/:uuid` | LTI session | Main content viewer. Iframes the content, sends `zest-context` via postMessage, relays grade/state/config messages between content and server. Supports external tab mode detection. |
| `GET` | `/editor/:contentId` | Instructor | Assessment config editor wrapper. Iframes `editorFile` from the content zip, sends context with current assessment config, relays config API messages. |
| `GET` | `/review/:contentId` | Instructor | SpeedGrader review wrapper. Iframes `reviewFile` (or `index.html`), sends context with `reviewMode: true`, submission data, and answer key. Query: `?sub=<submissionId>`. |
| `GET` | `/teacher-view/:contentId` | Instructor | Teacher student viewer. Lets instructors preview content as if they were a student, with optional answer key overlay. |

## Appendix: postMessage Protocol

Communication between the wrapper (parent) and content (iframe) uses `window.postMessage`. All messages have a `type` field.

### Wrapper to Content

| Type | Fields | Description |
|------|--------|-------------|
| `zest-context` | `context`, `assessmentConfig?`, `toolOrigin?`, `submission?`, `answerKey?` | User context and launch data. Sent on iframe load. |
| `zest-submit-result` | `_submitId`, `success`, `error?` | Response to a grade submission. |
| `zest-review-data` | `submission` | Submission data for review mode (legacy; now sent with `zest-context`). |
| `zest-state-save-result` | `_stateId`, `success`, `status?`, `hash?`, `updatedAt?`, `error?` | Response to a state save request. |
| `zest-state-load-result` | `_stateId`, `success`, `state?`, `hash?`, `updatedAt?`, `error?` | Response to a state load request. |
| `zest-state-delete-result` | `_stateId`, `success`, `error?` | Response to a state delete request. |
| `zest-config-load-result` | `_configId`, `success`, `config?`, `source?`, `error?` | Response to a config load request. |
| `zest-config-save-result` | `_configId`, `success`, `error?` | Response to a config save request. |
| `zest-config-delete-result` | `_configId`, `success`, `error?` | Response to a config delete request. |

### Content to Wrapper

| Type | Fields | Description |
|------|--------|-------------|
| `zest-resize` | `height` | Request iframe resize to the given pixel height. |
| `zest-submit` | `_submitId`, `score`, `options` | Submit a grade (score=number) or work (score=null). |
| `zest-state-save` | `_stateId`, `state`, `hash`, `assignmentId` | Save student state to the server. |
| `zest-state-load` | `_stateId`, `assignmentId` | Load student state from the server. |
| `zest-state-delete` | `_stateId`, `assignmentId` | Delete student state from the server. |
| `zest-state-beforeunload` | `state`, `hash`, `assignmentId` | Last-chance state save on page unload (handled by the wrapper via sendBeacon). |
| `zest-config-load` | `_configId`, `assignmentId` | Load assessment config from the server. |
| `zest-config-save` | `_configId`, `config`, `assignmentId` | Save assessment config to the server. |
| `zest-config-delete` | `_configId`, `assignmentId` | Delete assessment config from the server. |
